# المرحلة 32 — أساس ملكية تشفير Wi-Fi Aware داخل الخدمة

## ما أضيف
- إضافة `BlousabWifiAwareCryptoStore` كطبقة تشفير مستقلة صالحة لأن تملكها خدمة Android.
- تخزين مفاتيح الإرسال والاستقبال وبادئات Nonce وعدادات الاتجاهين داخل حالة جلسة متزامنة.
- نسخ مواد المفاتيح مرة واحدة عند التثبيت، مع رفض التثبيت فوق جلسة موجودة دون إزالة صريحة.
- تشفير AES-256-GCM مع الإبقاء على إصدار الإطار `BSAE` وبيانات AAD الحالية وترتيب Nonce الحالي.
- رفض الحزم المكررة أو الخارجة عن ترتيب العداد، ومسح مواد المفاتيح عند إزالة الجلسة.

## حد التنفيذ بوضوح
هذه إضافة تأسيسية مستقلة، وليست بعدُ نقلاً مكتملاً متصلاً بمسار المصافحة وTCP. لم تُحوّل `MainActivity` بعد إلى استدعاء هذه الطبقة، ولم تُحذف callbacks القديمة؛ إبقاؤها يمنع كسر الاتصال الحالي قبل إتمام ربط الخدمة واختباره. يجب أن تكون الخطوة التالية ربط `onVerified` بتثبيت الخدمة، ثم تحويل `adoptWifiAwareTcpSocket` إلى استخدام مخزن الخدمة، وإزالة الحالة القديمة فقط بعد نجاح اختبارات التوافق.

## التحقق
- مراجعة ساكنة لحدود أحجام المفاتيح والبادئات، مزامنة العدادين، AAD، ورفض إعادة التثبيت.
- لم يتم تشغيل Flutter/Gradle أو اختبار هاتفين في هذه البيئة؛ لا يُدّعى نجاح بناء APK.
