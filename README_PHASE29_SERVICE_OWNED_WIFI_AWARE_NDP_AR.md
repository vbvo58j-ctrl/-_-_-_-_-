# المرحلة 29 — نقل إدارة NDP وطلبات الشبكة إلى خدمة Android

## الهدف
نقل ملكية موارد مسار بيانات Wi-Fi Aware (NDP) من `MainActivity` إلى `BlousabBackgroundService` دون تغيير بروتوكول الهوية أو المصافحة أو تشفير الحزم، ودون تجاوز شرط اختيار المستخدم للجهاز.

## ما تغيّر
- أضيف `BlousabWifiAwareDataPathEngine.kt` لإدارة طلبات `ConnectivityManager.requestNetwork` و`NetworkCallback`.
- أصبح المحرك ينشئ `ServerSocket` لطرف النشر، وينشئ اتصال TCP الصادر لطرف الاشتراك عند ظهور `WifiAwareNetworkInfo`.
- أصبحت الخدمة توفر واجهات `startWifiAwareServerDataPath` و`startWifiAwareClientDataPath` و`closeWifiAwareDataPath`، وتملك المحرك ودورة حياته.
- أصبح إغلاق Wi-Fi Aware أو تدمير الخدمة يغلق طلبات الشبكة ومآخذ الاستماع التابعة للمحرك.
- تحولت دوال Activity إلى منسق سياسة: تتحقق من أن المستخدم اختار النظير وأن المصافحة موثقة، ثم تطلب من الخدمة بدء NDP وتستقبل المقبس الناتج لتسليمه إلى مسار الحزم الحالي.
- بقيت رسالة `BLOUSAB_READY` وتنسيق المصافحة ومفتاح PSK المشتق كما هي.
- أضيفت معالجة أخطاء عدم توفر الشبكة وفقدها، مع تنظيف موارد النظير وجدولة إعادة المحاولة الحالية.

## ما لم يتغير / الحدود المتبقية
- ما زال `MainActivity` يتولى قراءة TCP بعد تسليم المقبس، وتشفير/فك تشفير حزم Wi-Fi Aware، وإرسال الحزم وإدارة واجهة الأحداث.
- callbacks الخاصة بالمقبس والأحداث ما زالت تصل إلى Activity الحالية؛ لذلك نقل الموارد لا يعني بعد استقلال جميع أحداث البيانات عن إعادة إنشاء Activity.
- ما زال الاتصال يتطلب Android 10+ لمسار بيانات Wi-Fi Aware، ودعم الجهاز الفعلي لهذه التقنية.
- لم يتم تغيير اكتشاف LAN أو جعله Mesh؛ هذه المرحلة تخص دورة حياة NDP فقط.

## الفحوصات
- تمت مراجعة مسارات إنشاء وإغلاق المحرك وربطها بالخدمة وActivity.
- فشل تشغيل Gradle Kotlin compile لأن Gradle wrapper حاول تنزيل Gradle 8.14 ولم تتوفر الشبكة (`UnknownHostException: services.gradle.org`).
- لا يتوفر Android SDK/Flutter toolchain هنا؛ لذلك لم يتم الادعاء بنجاح `flutter analyze` أو بناء APK أو اختبار هاتفين.
- يلزم اختبار جهازين Android 10+ يدعمان Wi-Fi Aware: اكتشاف، مصافحة، اختيار صريح، اتصال NDP، تبادل رسائل، ثم إيقاف الخدمة وإعادة التشغيل.

## الخطوة التالية — المرحلة 30
نقل دورة حياة TCP reader/writer ومخازن الاتصالات المشفرة إلى الخدمة، مع واجهة أحداث محتفظ بها وإقرار استلام، ثم جعل Activity واجهة عرض فقط. يجب الحفاظ على ترتيب عدادات AES-GCM، وربط المفاتيح بهوية النظير، وشرط اختيار المستخدم.
