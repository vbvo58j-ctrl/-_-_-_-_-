# المرحلة 40 — حفظ أحداث Wi‑Fi Aware أثناء انفصال الواجهة

## التغيير
- أضيفت قائمة انتظار محدودة (100 حدث) لأحداث قناة بيانات Wi‑Fi Aware داخل `BlousabBackgroundService`.
- عند انفصال Activity/Flutter، لا تُسقط أحداث الاتصال والانقطاع والحزم فوراً؛ تحفظ مؤقتاً في الخدمة.
- عند إعادة ربط مستهلك الأحداث، تُفرغ القائمة بالترتيب إلى الواجهة الجديدة.
- إذا تعذر تسليم حدث، يعاد إلى القائمة ويتوقف التفريغ لتجنب فقده أو الدوران السريع.
- عند امتلاء القائمة يُحذف أقدم حدث قبل إضافة الجديد، لتظل الذاكرة محدودة.

## حدود وضمانات
- هذا تحسين لتسليم الأحداث عند إعادة إنشاء الواجهة، وليس تخزيناً دائماً؛ قتل عملية Android قد يفقد القائمة.
- حد 100 حدث يعني أن التدفق الكثيف جداً أثناء غياب الواجهة قد يؤدي إلى إسقاط أقدم الأحداث.
- لا يثبت هذا بقاء Wi‑Fi Aware بعد قتل العملية أو إعادة تشغيل الجهاز.
- لم يتغير تنسيق الحزم أو خوارزمية AES-GCM أو المصافحة.

## التحقق
- فحص ساكن للتأكد من أن أحداث dataConnected/dataPacket/dataDisconnected تمر عبر نقطة التسليم الجديدة.
- لم يُشغّل Kotlin/Gradle/Flutter build أو اختبار أجهزة فعلية في هذه البيئة.

## اختبار الجهازين
1. اتصل بهاتفين عبر Wi‑Fi Aware.
2. أعد إنشاء Activity في أحد الهاتفين أثناء تدفق الرسائل.
3. تحقق من تسليم الأحداث المتراكمة وعدم تكرار إنشاء جلسة NDP.
4. تحقق من سلوك القائمة عند تجاوز 100 حدث.
5. افصل الاتصال صراحةً وتحقق من وصول حدث الانقطاع.
